## 中文说明

本次预发布面向批量处理向量的 Python 和 Node.js 宿主，以及依赖内存配额、不可变代际或离线迁移的应用。Rust crate、CLI、Server 源码和 npm 使用 `0.9.4-beta.1`，PyPI 使用 `0.9.4b1`，npm 发布通道为 `beta`。

### Python 与 Node.js 绑定

- PyO3 升级至 0.30。Python wheel 使用 `abi3-py39`，支持启用 GIL 的 CPython 3.9–3.15。批量检索和两种批量插入入口接受与数据库 dtype 一致、使用本机字节序的二维 C 连续 `memoryview`。空矩阵仍须提供正确列数，已释放的视图和维度错误返回结构化诊断。
- Node.js 22、24、26 在同一平台复用 Node-API 8 模块。浮点库的批量接口接受 `Float32Array`，指纹库接受 `BigUint64Array`。两端均保留嵌套数组输入。绑定在调用时取得向量快照并向内核移交所有权；Python TQL 执行和批量写入的提交阶段释放 GIL。

以下示例向一个已有的二维 f32 Python 数据库插入两条向量：

```python
from array import array

matrix = memoryview(array("f", [1, 0, 0, 1])).cast("B").cast("f", (2, 2))
ids = db.batch_insert(matrix, [{"name": "x"}, {"name": "y"}])
```

### 查询、存储与恢复

- 混合与批量检索在准备 QuIVer 索引前校验原始参数和向量。非法查询曾可能触发建图，使原清单无法再打开。Hook 改写后的配置保留第二次校验。混合检索与文本算子统一要求 BM25 的 `k1 > 0` 且有限，`b` 在 `[0,1]` 内。
- 批量检索按整批保留的命中和 Payload 计入实例及共享工作区预算，包括单线程执行时累计的结果。超限批次返回错误并释放配额。QuIVer 建图与导航配置的容量诊断使用字节数，便于宿主决定是否缩小批次或增加预算。
- 直接调用 Rust `MemTable` 的插入、替换与补丁会在修改索引和槽位前校验 Payload 与唯一约束。恢复插入遇到 NaN 或无穷大向量时返回 `TDB_INVALID_VECTOR`，保留槽位和可用 ID。WAL 回放在事务最终状态上重建唯一索引，支持事务内交换唯一键。
- 发布代际清单时，重命名被拒绝返回 `not_committed`，重命名成功后父目录同步失败返回 `unknown`。离线迁移重试会核对完整 Pelorus 配置，包括图度数、导航和精排；目标配置变化返回 `TDB_MIGRATION_CONFLICT`。
- Markdown 中跨解析事件的行内 HTML 段落保留正文、行与来源范围。来源修订为空时，错误指向 `source_revision`。Server 在打开数据库前检查请求超时能否转换为有效截止时间。

## English

This prerelease targets Python and Node.js applications that process batches of vectors, and hosts that rely on memory quotas, immutable generations, or offline migration. The Rust crate, CLI and Server sources, and npm package use `0.9.4-beta.1`. PyPI uses `0.9.4b1` and npm uses the `beta` dist-tag.

### Python and Node.js bindings

- The bindings use PyO3 0.30. Python wheels use `abi3-py39` and support GIL-enabled CPython 3.9–3.15. Batch search and both batch insert methods accept two-dimensional, C-contiguous, native-endian memoryviews matching the database dtype. Empty matrices must match the column count. Released views and dimension mismatches return structured errors.
- Node.js 22, 24, and 26 share the Node-API 8 module for each platform. Batch APIs accept `Float32Array` for floating-point databases and `BigUint64Array` for fingerprint databases. Both languages retain nested-array inputs. The bindings snapshot inputs at the call boundary and transfer vector ownership to the core. Python releases the GIL during TQL execution and batch write commits.

To insert two vectors into an existing two-dimensional f32 Python database:

```python
from array import array

matrix = memoryview(array("f", [1, 0, 0, 1])).cast("B").cast("f", (2, 2))
ids = db.batch_insert(matrix, [{"name": "x"}, {"name": "y"}])
```

### Queries, storage, and recovery

- Hybrid and batch search validate the original configuration and vectors before preparing a QuIVer index. A rejected query could previously trigger a build and invalidate the published manifest. Configuration changes made by a hook are validated again. Hybrid search and text operators both require finite positive BM25 `k1` and `b` in `[0,1]`.
- Batch search charges retained hits and payloads across the whole batch to the instance and shared workspace budgets, including results accumulated by one thread. An over-budget request releases its reservation on failure. QuIVer build and navigation admission errors report byte counts so hosts can adjust batch sizes or budgets.
- Direct Rust `MemTable` inserts, replacements, and patches validate payloads and uniqueness before changing indexes and slots. Recovery inserts reject vectors containing NaN or infinity with `TDB_INVALID_VECTOR` and preserve slots and available IDs. WAL recovery rebuilds unique ownership from the final transaction state, including key swaps.
- A rejected generation-manifest rename reports `not_committed`. A directory sync failure after a successful rename reports `unknown`. Offline migration retries check the full Pelorus configuration, including graph degree, navigation, and reranking. A changed destination configuration returns `TDB_MIGRATION_CONFLICT`.
- Inline HTML spanning multiple Markdown parser events retains its text, line evidence, and source ranges. An empty source revision identifies `source_revision` as the offending field. Server startup validates that the configured timeout yields a representable deadline before opening the database.

### Installation, upgrades, and validation

```sh
python -m pip install "triviumdb==0.9.4b1"
npm install triviumdb@0.9.4-beta.1
cargo add triviumdb@0.9.4-beta.1
```

Current-format 0.9.3 databases open directly. The main file format remains 15, WAL 7, and the index container 1. Take a directory snapshot before upgrading. If opening returns `TDB_MIGRATION_REQUIRED`, follow the [offline migration guide](https://github.com/Astrmira/TriviumDB/blob/v0.9.4-beta.1/docs/migration.md) to migrate into a new directory. SDK dimension migration preserves the source dtype.

Local Windows validation covered queries, concurrency, fault recovery, the migration tool, Server HTTP, and installed Python and npm artifacts. The commit CI and tag workflows record the results for each platform. [Commit CI](https://github.com/Astrmira/TriviumDB/actions/workflows/ci.yml) · [Python and npm publishing](https://github.com/Astrmira/TriviumDB/actions/workflows/release.yml) · [Server artifacts](https://github.com/Astrmira/TriviumDB/actions/workflows/server-release.yml)

The Chinese and English READMEs show how TQL follows citations from semantic seeds and reranks the results. The `llms.txt` guide describes when to choose Pelorus. Issues and Discussions have bilingual forms, and the PR description check exempts authors with repository write access.
